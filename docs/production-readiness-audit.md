# Production readiness audit

Audit date: 2026-07-20. Scope: repository state through Sprint 3.5 plus this production-hardening
pass. “Fixed” means application controls and automated tests were added in this branch; it does not
mean an external service or infrastructure was deployed.

| Severity | Component / file                              | Current behavior and production risk                                                                                            | Required remediation                                                                                               | Status                                             |
| -------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| BLOCKER  | AI provider selection, `plugin-ai.service.ts` | Deterministic provider was the implicit default and could be configured in production, allowing fabricated responses.           | Fail closed and reject deterministic configuration/execution outside development/test.                             | Fixed                                              |
| BLOCKER  | Connector bootstrap, `connector.service.ts`   | Dummy CRM was registered and published in every environment.                                                                    | Do not register, expose, install, or execute development connectors in staging/production.                         | Fixed                                              |
| BLOCKER  | Plugin discovery, `plugin.service.ts`         | Dummy Echo was discoverable and executable in every environment.                                                                | Filter and reject development plugins outside development/test.                                                    | Fixed                                              |
| BLOCKER  | CRM integration                               | No real CRM connector existed; production could only use local Dummy CRM data.                                                  | Implement a real provider adapter with safe response mapping and no fake success.                                  | Fixed in code; external HubSpot smoke test NOT RUN |
| BLOCKER  | Environment validation, `security-config.ts`  | No staging environment, development URLs could be accepted in production, and database target was not validated.                | Validate environment, database, URLs, cookies, secrets, and development-feature policy at startup.                 | Fixed                                              |
| BLOCKER  | Webhooks, connector event endpoint            | Inbound events use user JWT and synchronous processing; there is no deployed persistent queue or provider signature adapter.    | Add provider-specific public webhook controllers, signature/replay verification, and persistent asynchronous jobs. | Open                                               |

| BLOCKER  | Background jobs                               | No production persisted queue, retries, dead-letter queue, or worker deployment exists.                                         | Implement queue port plus Redis/BullMQ (or managed equivalent), worker, health, and shutdown.                      | Open                                               |
| HIGH     | Health and orchestration                      | API had no separate liveness/readiness contract.                                                                                | Add `/health/live`, `/health/ready`, database/schema checks, and container health check.                           | Fixed                                              |

| HIGH     | Connector event processing                    | Event IDs are deduplicated, but events are not asynchronously processed and signature timestamp/replay windows are not applied. | Queue after persistence and implement provider signature policies.                                                 | Open                                               |

## Assessment

The repository is **not production-ready**. It is materially safer and suitable as a staging
candidate for the implemented authentication/plugin/agent/connector scope, but the open BLOCKERs
for distributed rate limiting, persistent background jobs, and production webhook security prevent
approval for public internet-facing production deployment.
