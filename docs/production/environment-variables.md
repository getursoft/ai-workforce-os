# Environment Variables

Sprint 5.0 Phase 2/28. This is a description of `apps/api/src/config/env.schema.ts`'s `DEFAULT_FIELDS` —
if this document and that file ever disagree, the file is authoritative (this doc is generated by hand
from it, not the other way around). Validated once at bootstrap by `AppConfig` (`config/app-config.ts`),
before the Nest application is created — a missing required-in-production variable fails fast with a
readable list of every missing field, not a cryptic runtime crash mid-request.

**Secret values are never printed.** `AppConfig.startupSummary()` only logs a per-group populated-field
count (e.g. `auth:6 storage:3`), never values.

Legend: **Req** = required in production/staging (fails startup if missing). Optional fields fall back to
their default in every environment, including production, unless noted.

## A note on two config systems (Sprint 5.0B: consolidated, not merged into one file)

`AppConfig` (`config/env.schema.ts`) and the legacy `SecurityConfig`
(`identity/infrastructure/security/security-config.ts`) are still two files, but as of Sprint 5.0B they
share one canonical field-name registry and one HTTPS-strictness policy — `env.schema.ts`'s `DEFAULT_FIELDS`
is now the single declared list of every environment variable the app reads (including everything
`SecurityConfig` needs), and its URL-type check has no localhost exemption, matching what
`SecurityConfig` has always actually enforced. The duplicate/dead field names this document used to warn
about (`PUBLIC_API_URL` vs `API_PUBLIC_URL`, `DASHBOARD_URL`, `TOKEN_ISSUER`/`TOKEN_AUDIENCE`) are gone —
each concept now has exactly one real name. `identity.module.ts`'s `SECURITY_CONFIG` DI token is now
derived from the single `AppConfig` instance's `.security` property instead of independently re-parsing
`process.env` a second time, so there is exactly one `SecurityConfig` object per process, not two that
could theoretically disagree. `SecurityConfig` still does its own additional, stricter validation for
auth-critical fields (unconditional presence regardless of environment, 32-byte secret minimums, the
`PLUGIN_SECRETS_ENCRYPTION_KEY` base64/length check, `DATABASE_URL` protocol/localhost/test-name checks) —
that part was deliberately left as-is rather than folded into the generic schema, since those rules are
security-critical and already had solid test coverage; folding them in was judged higher-risk than the
value it would add for this pass.
